Automação & Engenharia de Processo

Processos manuais e repetitivos reconstruídos como sistemas — com atenção a onde eles podem quebrar silenciosamente, não só a onde funcionam.

Em produção

Changelog de Release Automatizado

github actions graphql notion api

ProblemaCada release exigia revisão manual dos cards entregues e escrita do changelog à mão — repetitivo e sujeito a esquecimento.

ProcessoPipeline completo: GitHub Action dispara ao fechar a milestone, consulta GraphQL (mãe + sub-issues entre repos), agrupa por tipo, publica formatado no Notion.

Resultado0 changelogs escritos manualmente desde a implementação — processo determinístico, virou base pra uma 2ª automação (mover cards em lote pra "Done").
Em produção

Automações do Board (Projects v2)

workflow design systems thinking

ProblemaBoard dependia de passos manuais repetitivos — milestone, status, avisos de PR, arquivamento — cada um sujeito a esquecimento.

ProcessoArquitetei automações que se protegem mutuamente contra estado inconsistente, com prioridade explícita pra nunca "puxar pra trás" um card já avançado.

ResultadoCaso real de 0 de 50 subtasks travadas → causa raiz corrigida sistematicamente, não card por card.
Em produção

Auditoria Pós-Renomeação de Repo

debugging root-cause analysis

ProblemaRepo do board renomeado → várias automações falhando silenciosamente, sem erro visível.

ProcessoRevisei cada automação atrás de comparações de texto contra o nome antigo — uma classe de bug que nunca gera erro, só zero resultados.

Resultado7 de 9 automações afetadas encontradas e restauradas — incluindo uma checagem de segurança que nunca mais passava.

Dashboards & Métricas

Dados que viviam espalhados, sem tendência nem alerta, viraram painéis vivos com leitura de causa e efeito.

Em produção

Dashboard de Saúde da Plataforma

data visualization github pages

ProblemaMétricas de cadastro, engajamento e crescimento espalhadas, sem lugar único pra acompanhar evolução.

ProcessoPainel visual com formulário próprio de input semanal e backup exportável — única responsável pelo registro, sem duplicidade de fonte.

ResultadoIniciativa recente — o ganho já concreto é a existência do painel e do processo de medição, onde antes não havia nenhum registro histórico dessas métricas.
Em produção

Métricas de Time (ponta a ponta)

data pipeline apps script notion api

ProblemaMétricas de entrega viviam numa planilha manual sem tendência nem alerta — e um bug de escopo deixava um tipo inteiro de entrega invisível nos números.

ProcessoCorrigi o bug e reestruturei o pipeline (Apps Script + GraphQL do GitHub), publicando dashboard automático no Notion com comparação mês a mês.

ResultadoIniciativa recente — o ganho já concreto é ter métrica de time e board de acompanhamento implementados e rodando sem intervenção manual, onde antes não existia nenhum.
